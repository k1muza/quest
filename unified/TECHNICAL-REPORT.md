# Kingdom Quest — unified interactive implementation

## Consolidation and source of truth
The approved environment is retained unchanged: original camera projection, 158 terrain cells, 35 route cells, continuous heightfield, bridge and courtyard. Source remains declarative in the historical environment directory; unified code reuses its geometry and projection rather than reproducing the old flat renderer. The optional depth-only switch in `environment/render_world.py` reruns the exact original geometry construction and exports a 1920×1080 depth image. Existing environment builds retain their prior default behaviour. This branch starts from complete import `3cda3c43f5a3924a57efb7f470ffcbbdcc56308f`, which includes the supplied documentation baseline and all binary assets.

## Route and stops
1,932 samples, 3,071.127 world-unit arc length, including interpolated heightfield and 41-point original bridge deck profile. All points retain world x/y/z, projected x/y, camera depth and cumulative 3D arc. Stops are equidistant in 3D and generated independently at runtime. The selected camera equations are x_screen=x, y_screen=283+z*cos−height*sin and depth=height*cos+z*sin. Projection maximum error from rounded JSON: 0.000011 units. Nearest sample to the bridge centre: 0.000042 units; gate centre: 0.303 units. Original surface validation rerun: 3,956 road and 941 river samples, zero out-of-tolerance, worst outside distance 0.001805 model units. Separate original bridge deck samples are preserved. Minimum projected marker separation: 69.85 / 59.17 / 46.08 / 40.06 pixels for 30 / 40 / 50 / 60 stops. See `qa-results.json` and `surface-validation.json`.

## Rendering and occlusion
A separate static background image (never redrawn by the renderer), cached marker canvas, and dynamic Canvas2D layer share the same responsive viewport and pan/zoom transform. Scene depth is an RG 16-bit fixed point image, decoded to Float32Array once. Every visible pawn pixel is tested against scene depth using the corresponding lathed pawn mesh relative-depth raster. Marker/shadow masks approximate the local ground plane and use a 2.4-unit tolerance. This correctly clips front scenery while preserving unobscured pixels behind it; no global foreground mask or WebGL. The selected camera's depth raster is native resolution; supersampled colour edges can show small halos. Some road engravings are occluded by actual scenery, so their numbers are reproduced on restrained attached wayfinding plaques. Ties allocate stable local slots relative to the path direction and a small coloured/symbol roster identifies all pieces, even when the gate or narrow road hides part of a pawn. Formations use visual offsets, not a general collision solver; six large pawns cannot be physically separated on every narrow deck without compromise. Depth-tested token positions remain on or close to the route rather than intentionally traversing scenery. Approximate upper-pawn visibility sampling found 20 of 1,932 samples with a foreground obstruction and longest contiguous span 28.05 world units; this is a heuristic, not a per-object collision proof.

## Performance and validation
Exact standalone bundle: 1,983,941 bytes (~1.98 MB decimal, approximately +0.32 MB versus 1.66 MB earlier environment). Packed scene depth, pawn sprite/depth and route metadata replace the old height-grid payload in runtime. Chromium 144.0.7559.96, headless Linux, 1920×1080 device scale 1: 240-frame sample median 16.7 ms / p95 16.7 ms, measured cadence 59.88 FPS; initialization decode 161.6 ms; Chromium JS heap estimate 31.2 MB (does not include all browser/GPU allocations). 41/41 automated checks passed, including 720p, 1080p, 4K CSS layout, fullscreen, no external requests, no JS errors, score under/overflow, authoritative completion, undo and rapid movement reconciliation. This is not a physical Smart TV compatibility test. Low quality halves dynamic overlay resolution; ambient effects can be turned off; with no motion/effects the overlay avoids unnecessary repainting. Renderer uses modern Canvas2D and JS, CSS container units; older TV browsers may require compatibility adaptations.

## Limitations and deferred details
Preserve the approved environment instead of introducing another terrain redesign. Targeted rock, harbour, township and castle architecture changes were deferred as expressly secondary; the ceremonial finish is a distinct gold marker and presentation spotlight rather than a newly modeled monument. Baked background and depth are camera-specific; zoom/pan is 2D, not freely orbitable. Depth tolerance and plane approximations can clip some pixels incorrectly at edges; ties are supported by a roster, not all six pawns always fully visible. Windmill, flags, chimney smoke and coastal wave geometry are static; only restrained visible-water highlights are animated. No transport, pairing, multiplayer sync, Flutter or Game Night changes. No external session ordering or conflict resolution is provided; the authoritative caller is responsible for ordered snapshots. See STATE-API.md.
