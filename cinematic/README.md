# Quest Cinematic Lab

Experimental offline 2.5D presentation build based on the unified board. Open `kingdom-quest.html` in a desktop browser. Press O to access the operator panel, then the Cinematic lab controls. Standard uses baseline artwork; Enhanced uses 1440p golden-hour artwork; Cinematic uses 4K WebP with JPEG fallback. All three share authoritative game state. Cinematic events are opt-in. Bridge/citadel camera buttons switch matched backgrounds, projection, depth and pawn sprites. The sequence demo awards points to the active team. Press R for camera reset; C toggles clean map; F fullscreen.

## Reproduce

From the repository root, install `requirements.txt` (NumPy, SciPy, Pillow, Numba and existing environment dependencies), plus Chromium/Playwright and FFmpeg for tests/recording. Run:

```
python cinematic/bake.py
python cinematic/build.py
python cinematic/regression.py
python cinematic/qa_cinematic.py
python cinematic/record_demo.py
```

The bake executes the geometry-generation section of `environment/render_world.py` up to its depth-only export marker, preserving the approved layout and placement logic. No source model assets are added. The build composes the existing unified engine and the presentation extension; it does not modify the baseline. Rendered source images and benchmark encodings are regenerated by the bake. Browser tests save screenshots, metrics and comparisons. `CHROMIUM` can select the browser executable. The bundle embeds all runtime resources.

Optional Blender bridge (not executed in lab): `python cinematic/bake.py --mesh` exports `cinematic/scene.npz`. With Blender 4.x or later and NumPy available, use `blender -b -P cinematic/blender_import.py -- cinematic/scene.npz cinematic/day.blend CYCLES day`; repeat with `gold` or `cinematic`, or `BLENDER_EEVEE_NEXT` for Eevee. The export contains exact triangulated geometry and baked face palette, not the original UV/PBR material system. No Blender results are claimed.

## Public interface

Existing `quest` state API unchanged. Additional presentation-only methods: `quest.cinema.setProfile(name)`, `setLighting(name)`, `changeView(name, landmark?)`, `glide(distance, zoom, durationMs)`, `overview()`, `followActive()`, `setAuto(boolean)`, `state()`, `sequence(points)`. View/profile/light changes return promises. `state().viewReady` indicates completion. `sequence` is an explicit demo score award, not a presentation-only state update; use existing external `applyState` for real gameplay. The automatic camera never changes scores or winner IDs.

See [research report](RESEARCH.md), [original regression](qa-results.json), [cinematic QA](cinematic-qa.json), [bake results](bake-results.json) and `gallery/` for visual evidence. No main merge or Game Night integration.
